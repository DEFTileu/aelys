# Goal: оптимизация Aelys на всех платформах

Готовый промпт для `/goal`. Это общая цель с последовательными проверяемыми
этапами. Работа над одним этапом не отменяет остальные части цели.

```text
Работай в <repository-root>.

Цель: оптимизировать и стабилизировать весь существующий Aelys — FastAPI/backend,
PostgreSQL/локальное SQLite-хранилище, shared TypeScript/client sync, React web,
macOS Tauri/Rust и Android APK. Доведи до работающих и проверенных локальных
сборок. Выполни реализацию, а не только аудит или план.

Прочти AGENTS.md, README, документы PROJECT_CONTEXT, DECISIONS, OPEN_QUESTIONS,
PRD, ARCHITECTURE, IMPLEMENTATION_PLAN, DATA_MODEL, API_CONTRACTS, SYNC_PROTOCOL,
SECURITY, GIT_WORKFLOW, актуальные platform README и отчёты в docs. RELEASE_REPORT
считай историческим свидетельством: проверь всё по текущему checkout. Сохрани
имеющиеся незакоммиченные изменения. Общую цель выполняй последовательными
срезами соответствующих milestones; у каждого — отдельные проверки и отчёт.
Разрешаю до шести субагентов с непересекающимися файлами. Интеграцию и Git index
контролирует главный агент.

1. Сначала воспроизводимый baseline.
Инвентаризируй реально работающие модули, запуск, зависимости, миграции, SDK,
сборки и платформенные ограничения. Создай OPTIMIZATION_PLAN.md с приоритетами
и OPTIMIZATION_REPORT.md с исходными замерами. Используй изолированные базы и
синтетические данные, не личные записи. Зафиксируй версии, dataset, команды,
warm/cold сценарии и число повторений. Измерь API p50/p95 и запросы к БД на
ключевых сценариях, фронтенд bundle/gzip и загрузку/интерактивность рабочих
экранов, desktop startup/idle CPU/RSS, APK size/startup и поведение при возврате
из фона. Недоступные замеры явно пометь как отсутствующие; не выдумывай цифры.

2. Backend и данные.
Исправь подтверждённые узкие места: лишние/N+1 запросы, индексы по реальным
планам запросов, пагинацию, транзакции, пул соединений, блокирующий I/O,
таймауты, отмену, утечки соединений/задач и неконтролируемые повторы. Сохрани
ownership/device permissions, версии, стабильные operation keys, UTC/IANA,
DecimalMoney и безопасные миграции. Проверь SQLite и PostgreSQL на изолированных
базах. Изменения API сопровождай типами, OpenAPI и тестами. Не добавляй Redis,
очереди или микросервисы без измеренной необходимости.

3. Shared, sync и frontend.
Проверь durable local storage, outbox, конфликты, повторные запросы и cache
invalidation. Сохраняй безопасные online-only ограничения до доказанной
идемпотентности сервера; не включай автоматический replay legacy POST.
Сократи подтверждённые повторные запросы, лишние рендеры, тяжёлые зависимости и
ненужные загрузки. Применяй splitting/виртуализацию/кеш только при измеренном
эффекте и корректной инвалидации. Проверь большие списки, поиск, формы,
loading/empty/error/offline/conflict, потерю соединения, reload и возврат назад.
Действия сохраняют данные; сетевые ошибки не выдают ложный успех.

4. macOS.
Собери и запусти актуальное Tauri-приложение, проверь реальные вызовы backend,
хранение/восстановление сессии, закрытие/повторный запуск, sleep/wake, обработку
сети, завершение дочерних процессов и фоновых задач, загрузку CPU/памяти в покое.
Оптимизируй по профилированию. Подготовь локальный .app, а доступный installer —
если хватает инструментов. Debug/release, bundled/unbundled и signed/unsigned
покажи раздельно. Подпись/notarization не имитировать. Mac runtime остаётся
fail-closed до фактической проверки изоляции и доверенных grants.

5. Android APK.
Проверь JDK/Android SDK/NDK и текущее состояние Tauri Android. Настрой доступный
локальный toolchain, собери настоящий устанавливаемый APK. Host cargo check
не считается Android-сборкой. Запусти APK на доступном эмуляторе или устройстве;
проверь вход, доступность backend с устройства (его localhost отличается от
Mac), CRUD, смену сети, background/resume, restart и сохранение локальных данных.
Проверь permission flows и WebView security. Не меняй wrapper с Tauri на другой
без отдельного обоснованного spike и решения владельца. Сохрани APK и SHA-256,
укажи ABI, build variant и статус подписи. Не включай общий cleartext bypass,
не публикуй backend в интернет ради теста и не отключай certificate validation.

6. Общая проверка и измеримый результат.
После каждого исправленного среза сравни те же сценарии с baseline; учитывай
вариацию между прогонами и регрессии на остальных платформах. Проведи web E2E
и существенные API/sync/platform проверки. Выполни backend pytest/Ruff/mypy/
Bandit, shared/web tests/typecheck/build, OpenAPI/migrations и применимые Rust
fmt/test/clippy/build с существующими lockfiles. Проверяй реальные исполняемые
артефакты, а не только успешную компиляцию общего кода. Обновляй документацию
только по фактическим результатам. Не дублируй дорогие проверки без причины.

Ограничения:
- Сохрани последний согласованный UI: собственные SVG Aelys, обои только на Home,
  понятные заголовки без лозунгов, изменение виджетов только через Customize,
  фиксированная сетка и готовые размеры. Используй применимые установленные
  skills; UI-фреймворк и полный редизайн ради оптимизации не требуются.
- BYOK/OAuth/Telegram credentials не попадают в frontend cache, логи или LLM tools.
  Полные Mac agent transcripts и embeddings остаются на Mac. Policy Engine и
  sandbox/grants не ослабляются ради скорости. Сохрани single-owner auth.
- Внешние live-интеграции проверяй только при уже доступных разрешённых credentials.
  Mocks допустимы в тестах, но не как доказательство настоящей интеграции.
- Сохраняй личную БД, ключи и аккаунт. Для browser QA используй отдельную БД и
  отдельный hostname/context: другой порт сам по себе не изолирует auth cookies.
- Не запускай следующие UX-redesign goals и новые продуктовые модули. Банковские
  выписки/Kaspi отложены. Новые библиотеки, переезд архитектуры, DEPLOY, git push,
  публикация приложений и внешняя отправка сообщений не входят в эту цель.
- Не превращай OPEN/PROPOSED решения в DECIDED. Если нужен недоступный SDK,
  сертификат, лицензия, credential или устройство — запиши точный блокер,
  выполни всю независимую работу и оставь неподтверждённый gate открытым.

Критерий завершения: измеренные узкие места исправлены и проверены, существующие
основные сценарии не сломаны, доступны web/backend, macOS-приложение и Android APK;
runtime/platform gates подтверждены в соответствующей среде. Если хотя бы одна
обязательная платформа или проверка заблокирована/не проверена, общая цель ещё
не завершена: отчёт должен точно показывать сделанное и оставшееся.

Итог: OPTIMIZATION_REPORT.md с таблицей before/after и методикой, исправлениями,
командами/результатами, скриншотами, путями к .app/APK и checksum, локальными
URL/портами, ограничениями и остаточными рисками. Дай понятную инструкцию запуска
web/macOS/Android. Продолжай автономно в рамках разрешённого объёма; не заканчивай
только списком рекомендаций и не объявляй готовность без evidence.
```
