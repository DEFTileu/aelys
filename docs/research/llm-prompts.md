Phase 4 / task 5, 25 ноября 2026. Инвентарь построен по местам формирования сообщений и вызовам complete, stream, one_shot_json и complete_json на базе ab80544. Для воспроизведения нужны изменения этого стека, включая lazy tools, trusted time, публичные источники и пагинацию групповой истории. Перечень схем и серверных ограничений приведён в [AI_TOOL_INVENTORY](../AI_TOOL_INVENTORY.md).

## Что применено из первичных источников

OpenAI рекомендует различать полномочия сообщений, отделять контекст от инструкций и проверять поведение на характерных примерах. В English сохранённые слова, темы и тексты заданий теперь передаются как поля входного JSON в сообщении с пользовательскими данными. [OpenAI, Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering)

Anthropic рекомендует прямо задавать роль, формат и структуру входных данных. В группе инструкция теперь учитывает поддержку инструментов выбранной моделью. Для Focus описаны результат при недостатке сведений и роль сервера в разблокировке. В общем XML-контейнере экранируется текст, чтобы цитата не могла закрыть тег. [Anthropic, Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)

Правила интеграции для неё — письмо передавать как данные, проект задачи отделять от создания и проверять сроки по времени исходного сообщения.

## Границы проверки

Синтетические тесты проверяют роли и содержимое запроса на границе провайдера, XML с поддельной инструкцией и заявлением об успехе, семантику pending_approval, DST и локальную полночь, текстовую модель и разрешённые инструменты. Они не измеряют вероятность следования инструкциям конкретной облачной модели. Для такого измерения нужна отдельная серия ответов на одинаковые фиктивные запросы с фиксированными версиями моделей.

При интеграции проверена граница Knowledge. Сервер передаёт отобранные excerpts и отключает схемы инструментов для этого запроса, даже если модель поддерживает вызовы и разговору разрешены личные источники. Сценарий проверен на уровне HTTP payload. Серверный scope прямой записи ограничивает класс операций, а проверка соответствия аргументов запросу пользователя остаётся частью поведения модели.

## Локальная проверка

Из каталога backend, с зависимостями из uv.lock:

```sh
uv sync --frozen --extra test --extra quality
.venv/bin/python -m pytest -q -rs tests/ai_automation tests/test_ai_time_context.py \
  tests/test_telegram_group*.py tests/test_focus_unlock.py tests/test_telegram_guest*.py \
  tests/test_companion_voice*.py tests/test_telegram_secretary.py tests/test_telegram_ai.py \
  tests/test_answer_trace_sources.py tests/test_telegram_task_suggestions.py \
  tests/test_telegram_chat_commands.py tests/test_automation_draft.py tests/test_english*.py \
  tests/test_telegram_personal_dialogue.py tests/test_personal_tools.py
```

| Синтетический случай | Наблюдаемая проверка |
|---|---|
| Цитата содержит закрывающий тег и ложное подтверждение создания заметки | XML разбирается в единственный узел данных. Системное сообщение не содержит подставленный текст. |
| Модель после поиска пытается создать запись | Подставной адаптер получает отказ сервера, список выполненных записей пуст. |
| App вызывает create_note и complete_task | Ответ инструмента содержит pending_approval. Изменение проходит отдельный endpoint approve. |
| Вчера в Алматы и в Нью-Йорке при переходе на летнее и зимнее время | Границы суток построены по двум локальным полуночам с соответствующими UTC-смещениями. |
| Текстовая модель в группе и Guest | Групповой промпт не предлагает вызвать history. В Guest без маркера запрос уходит без tools. С маркером, требующим личных scopes, вызова модели нет. |
| Focus получает фиктивное решение о выдаче 600 минут | Сервер применяет максимальную длительность и дневное ограничение из своей конфигурации. |

Отдельный тест test_model_claim_of_creation_cannot_execute_a_pending_note подставляет ответ «I created the Agenda note» сразу после pending_approval. Он проверяет, что предложение остаётся pending и таблица заметок пуста. Свободный текст ответа по-прежнему может содержать ошибочное утверждение модели. Сервер гарантирует состояние записи, а качество формулировки требует оценки реальных ответов.
