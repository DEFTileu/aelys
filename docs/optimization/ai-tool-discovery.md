# Выдача инструментов AI-агенту Aelys

Phase 4, задача 3 из IMPLEMENTATION_PLAN. Срез касается существующих типизированных
инструментов. Состав прав по каналам описан в [реестре](../AI_TOOL_INVENTORY.md).
Решения о новых интеграциях остаются открытыми.

## Как это устроено у других

- Claude Tool Search держит часто используемые инструменты в контексте и подключает
  полные схемы остальных по запросу. Anthropic рекомендует проверять подбор схем на
  реальных сценариях, давать инструментам различимые имена, объяснять аргументы и возвращать
  модели достаточно данных, чтобы она понимала, что делать дальше.
  [Tool Search](https://www.anthropic.com/research/advanced-tool-use),
  [дизайн инструментов и evals](https://www.anthropic.com/research/writing-tools-for-agents).
- В OpenAI Tool Search полные схемы раскрываются по мере необходимости. Приложение может
  выполнять поиск по своему каталогу и решать, какие схемы вернуть. Для агентских систем
  OpenAI выделяет инструменты получения данных, действий и оркестрации. У coding-агента
  среда выполнения отдельно ограничивает доступ к файлам, сети и учётным данным.
  [Tool Search](https://developers.openai.com/api/docs/guides/tools-tool-search),
  [руководство по агентам](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/),
  [ограничения среды](https://developers.openai.com/api/docs/guides/agents-api/environments/security).
- В Claude Code правила применяются к инструменту и его аргументам. Чтение рабочего
  каталога и изменение файлов имеют разные правила. В MCP клиент получает схемы через
  `tools/list` и вызывает выбранный инструмент через `tools/call`. Если HTTP-сервер
  требует авторизации, токен выдаётся для конкретного сервера.
  [Claude Code Permissions](https://code.claude.com/docs/en/permissions),
  [MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools),
  [MCP Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization).

## Как работает Aelys

1. Канал формирует реестр и текущие права. Сервер проверяет доступ к каждой схеме.
2. При восьми и более разрешённых инструментах сразу доступны базовые операции,
   в том числе поиск задач и заметок, чтение календаря, создание задачи и заметки.
   При наличии соответствующих прав модель также сразу получает веб-поиск и команды
   памяти. В меньших каталогах все разрешённые схемы доступны сразу.
3. `load_tools` содержит имена и короткие назначения отложенных схем. Модель может
   выбрать до четырёх за один вызов. Схемы появляются со следующего обращения к модели,
   действуют до конца текущего хода и добавляются к исходному списку. Один запрос на
   загрузку не даёт доступ к закрытым данным и сам ничего не записывает.
4. Каждое действие снова проходит Policy Engine с фактическими аргументами. AI Chat
   создаёт предложение на изменение, где требуется подтверждение. Результаты
   инструментов остаются недоверенными данными. Поиск схем занимает один шаг и
   учитывается в общем бюджете выполнения.

Отложенные схемы — `update_task`, `complete_task`, `create_event`, `create_reminder`,
`search_knowledge` и `read_chat_history`, если текущий канал разрешает их. Погода и курсы
тоже подгружаются по запросу в больших каталогах.
Telegram
без маркера владельца может получить веб-поиск, а голосовой Companion получает
свой небольшой каталог сразу. Реализация общая для адаптеров Claude и OpenRouter.

«Какие задачи были вчера?» использует дату сервера в часовом поясе пользователя и
сразу доступный `list_tasks`. «Заверши отчёт и напомни о задаче на завтра» может потребовать
схемы завершения и напоминания. Их можно запросить вместе, после чего модель
получит типы аргументов и правила и сможет продолжить.

Проверки с управляемыми ответами провайдеров покрывают передачу схем, выбор набора,
отказ при выборе недоступной схемы, вызов только со следующего шага, сброс выбора на
новом ходе и подтверждение записи. До добавления погоды и курсов при включённых задачах,
календаре и заметках первый
запрос передаёт 7 схем вместо 10. Их компактное представление в JSON занимает 4 548
байт вместо 7 644 (−40,5%), включая схему `load_tools`. При включённой базе знаний
получается 4 632 вместо 7 972 байт (−41,9%). Это размер только схем. Качество выбора
инструментов, задержка и стоимость на реальных моделях пока не измерены.
