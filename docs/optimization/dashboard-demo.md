# Dashboard: локальные демонстрационные данные

Задача: Phase 3 / Dashboard personal modules. Владелец 2026-10-31 явно попросил
моковые данные, чтобы оценить заполненные виджеты и их адаптацию.

## Реализация и границы

- `dashboardDemo.ts` создаёт типизированные вымышленные примеры: 6 задач,
  3 события на текущую дату, 3 связанных проекта, 4 заметки, 4 операции в KZT,
  3 письма на адресах `example.test`, 4 события активности. Суммы — строки;
  баланс 161450.00 KZT вычисляется существующим точным денежным helper.
- `HomeView.tsx` включает примеры через кнопку «Показать демо» или `?demo=1`.
  Баннер явно сообщает о деморежиме и его ограничении одним Dashboard.
  «Показать мои данные» возвращает настоящие записи.
- `DashboardDemoWeather.tsx` показывает отдельно помеченный вымышленный прогноз.
  Настройки погоды и реальный provider не используются для этих примеров.
- Задачи и таймер интерактивны только в React state. Перезагрузка сбрасывает
  изменения. Демо-записи не передаются API, cache или outbox. Включённое демо
  пропускает загрузку настоящих Dashboard-списков; при выходе они обновляются.
- Доступно только в loopback Web development с существующим launch marker.
  Авторизация остаётся обязательной. Production/native игнорируют demo query.
- Существующие порядок, размеры и ручные настройки виджетов сохраняются.
  Письма доступны в виджете Mail, если он добавлен пользователем. Ссылки на
  другие разделы открывают настоящие данные этих разделов.

Новых архитектурных решений, API и миграций нет. OPEN / PROPOSED не менялись.
Это демонстрация Dashboard, а не утверждение о работе почтовой интеграции,
прогноза погоды или других внешних сервисов.
