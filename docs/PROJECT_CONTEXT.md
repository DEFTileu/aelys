# Aelys — PROJECT_CONTEXT

## 1. Происхождение идеи

Пользователь хочет **единую личную систему наподобие Notion по функциональной полноте**, но не клон Notion: одна платформа для работы, учёбы, разработки, организации повседневной жизни и AI. Проект носит официально выбранное название **Aelys**. Дизайн будет создаваться отдельно; сейчас требования исключительно функциональные. Пользователь один (single-user по продукту), но проект публикуется целиком как open source, чтобы сторонние пользователи могли разворачивать собственные экземпляры.

## 2. Подтверждённые продуктовые решения (DECIDED)

- Весь исходный код открыт: web, macOS, Android, backend, runtime, документация. Возможность самостоятельного размещения (self-hosting).
- Единые **Projects**: внутри одного контекста связаны задачи, заметки, документы, события, агентские сессии, история изменений и при необходимости Git-репозитории. Личные записи могут существовать без проекта.
- Единый AI-ассистент с инструментами модулей; в перспективе специализированные агенты.
- Пользователь подключает **собственные API-ключи** Claude, OpenRouter и других провайдеров; автоматический выбор модели по типу задачи с контролем затрат.
- Модули первого целевого релиза: Projects, Notes, Tasks, Calendar, AI Chat, Mail, Finance, Timer, Telegram; дополнительно Dashboard, Search, Settings, Devices необходимы как системные функции.
- Предпочтение собственным модулям; внешние интеграции следует включать по мере готовности, не ставить их условием разработки ядра.
- Web + macOS + Android, устанавливаемый Android APK; автоматическая синхронизация между устройствами, offline-first для всего, что может реально работать без сети.
- Поддержка локальных агентов **Claude Code** и **Codex CLI**: история сессий + возможность запускать/контролировать процессы на Mac с других устройств.
- **Сырые/полные данные истории агентских сессий хранятся на Mac**. В облаке только минимальный индекс/метаданные, а не содержание сообщений/кода и не семантические embeddings, способные раскрывать содержание.
- Разрешается запуск и работа агентов **без подтверждения каждой команды внутри заранее явно выбранных проектов**. Это не означает неограниченный доступ ко всему Mac, секретам или внешним сервисам. Настройка границ доступа обязательна.
- Rule-based automation: действия, заранее разрешённые правилами, выполняются автоматически; исполнитель, а не LLM, проверяет права.
- Не обсуждаем UI-дизайн и поиск/тарифы VPS на текущем этапе.

## 3. Стек (утверждено/кандидаты)

- **DECIDED:** React + TypeScript, Python + FastAPI, PostgreSQL (внешняя по отношению к серверу приложений), macOS через **Tauri 2 + Rust**.
- **PROPOSED:** React + Vite для максимального повторного использования UI; SQLite для macOS/Android, IndexedDB для Web; SSE для AI-событий, WebSocket для Mac-runtime канала.
- **OPEN:** финальный Android wrapper: Tauri 2 допустимый кандидат, но требуется spike уведомлений, фоновой синхронизации, системного хранилища ключей и APK. Если не проходит — оценить Capacitor.
- **PROPOSED:** модульный монолит FastAPI с отдельным локальным macOS runtime/helper; поиск через PostgreSQL FTS, локальный SQLite FTS, затем pgvector только по разрешённым данным.
- **OPEN:** точный AI SDK/harness (важна независимость от модели, а не навязанная библиотека).

## 4. Требуемые модули

- **Dashboard:** события, задачи, избранные проекты, статус синхронизации, daily briefing.
- **Projects:** контекст, связанные ресурсы, собственные/привязанные репозитории и агентские сессии.
- **Notes/KB:** Markdown, вложенность/структура, версии, теги, вложения, внутренние ссылки, поиск.
- **Tasks:** задачи/подзадачи, дедлайны, приоритеты, повторения, статусы, проекты.
- **Calendar:** события и напоминания; локальный календарь сначала, Google Calendar позднее.
- **Mail:** письмо, черновики, поиск, AI-анализ и создание задач из писем; подключение Gmail ещё не утверждено для MVP.
- **Finance:** ручные доходы/расходы, счета, категории, бюджеты, валюты; банки не обязательны для MVP.
- **Timer:** Pomodoro, секундомер, интервалы, связь с задачами и статистика.
- **Telegram:** личный бот для capture/команд/уведомлений; для настоящей работы нужен Telegram Bot API и сеть.
- **Search/History:** общий поиск по разрешённым ресурсам, история изменений и действий.
- **AI:** AI-чат, инструменты, BYOK, модельный роутер, стоимость, доступ к проектам и знаниям.
- **Mac Agents:** локальное чтение и поиск историй Claude Code/Codex, удалённый запуск в выбранных проектах, вывод статуса и событий.
- **Automations:** правила trigger/conditions/actions, audit и лимиты.
- **Utilities/Infra Monitor/University Hub/Voice:** полезные идеи на дальнейшие версии, **не часть утверждённого обязательного MVP**.

## 5. Несколько эталонных пользовательских сценариев

1. Создать задачу на Mac без интернета → позднее увидеть её на Android и в Web без дублей.
2. Спросить с Android «Что вчера делал Codex в BYTAN?» → live-запрос Mac, поиск только в локальных сессиях, ответ с источниками; если Mac offline — корректное ограничение.
3. Запустить Codex из телефона в заранее разрешённом репозитории → смотреть прогресс, отменить, увидеть результат без подтверждения каждой безопасной команды внутри политик sandbox.
4. Получить письмо → AI выделяет потенциальный дедлайн → по правилу создать задачу либо показать предложение.
5. Связать заметку с задачей, проектом, событием календаря и конкретным агентским запуском.
6. Работа с финансами, таймером и локальными заметками без интернета; сетевые операции откладываются.
7. Включить правило: `agent.run_completed` → сохранить результат в историю проекта и уведомить Telegram.

## 6. Не путать две цели

- **Assistant AI**: читает разрешённые данные, отвечает и вызывает инструменты Aelys через API.
- **External coding agents**: Claude Code и Codex CLI, исполняемые на Mac через отдельный runtime. Синхронизация истории и remote execution — разные разрешения и процессы.

## 7. Текущая стадия

Исследование функциональности завершено достаточно для engineering design. Документы этого комплекта — спецификация v0.2, а не утверждение, что система реализована или что всё проверено на реальных устройствах. Следующее: закрыть OPEN-вопросы, создать vertical slice ядра и тесты.
