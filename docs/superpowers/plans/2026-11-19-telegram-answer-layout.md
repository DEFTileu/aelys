# Telegram: краткий ответ, раскрывающиеся подробности и остановка

## Задача и согласованное поведение

Продолжение Phase 4 / run orchestration and cancellation. Владелец утвердил
реализацию по показанному примеру: краткий естественный вывод сверху,
подробности длинного ответа в раскрывающейся цитате, «Как я ответил» снаружи.
Короткие ответы не дублируются. Полный сохранённый ответ доступен в Mini App;
если сообщение не помещается в Telegram, сокращение обозначается явно.
Во время работы — обычный emoji, текущий поиск и кнопка «Остановить».
Маскота создаёт владелец отдельно. Область: личный диалог и Guest Mode.

## План исполнения

1. Общий форматтер Telegram: UTF-16 entities, summary/details, ограничения длины,
   сохранение форматирования и источников в существующем Mini App.
2. Подсказка модели: сразу ответ по существу, краткое резюме первым абзацем,
   подробности только при необходимости; без отдельного запроса LLM на summary.
3. Обновляемый статус и завершение в том же сообщении. Guest: единственный
   answerGuestQuery, затем editMessageText через inline_message_id.
4. Owner-only callback остановки, связанный с конкретным активным запуском и
   сообщением. Старые/поддельные callbacks не отменяют другой запуск.
   Отмена не обещает откат уже выполненных действий.
5. Проверки транспорта, форматирования, отмены, Guest delivery/recovery и
   регрессии личного диалога. Перекрёстная проверка GPT-6.1 Sol / GPT-6.2 Sol.
6. Отчёт о проверках и отдельное указание живой проверки Telegram.

## Границы

Новые схемы БД и миграции не запланированы. Правила owner-only и суффикса aelys
не меняются. Ветка истории не сливается. BotFather и создание маскота остаются
за владельцем. Реальная Telegram-проверка не заменяется mock-тестами.

## Реализация

- Общий форматтер `presented_answer_message`: краткий первый абзац остаётся
  раскрытым; подробности длиннее 600 UTF-16 единиц сворачиваются. Строки с
  code/pre/ссылками остаются раскрытыми, чтобы не создавать запрещённые Telegram
  пересечения entities. Исходный ответ сохраняется без сокращения.
- Статус и поисковый этап содержат ссылку на trace. Она станет доступна после
  завершения запроса; при ошибке финального редактирования сохранённый ответ
  остаётся доступен по уже отправленной ссылке.
- Кнопка Stop привязана к владельцу, интеграции, боту, запуску и хэшу сообщения.
  Изменение статуса run сериализуется с транзакцией инструмента. Это остановка
  продолжения, а не откат уже зафиксированной записи.
- Неопределённый результат отправки не вызывает повторное сообщение. Финальное
  редактирование того же сообщения получает одну ограниченную повторную попытку
  при сетевом сбое. Длительная недоступность Telegram остаётся ошибкой доставки.
- Guest target хранится зашифрованным в существующем metadata запуска для
  завершения статуса после перезапуска. Запросы и инструменты не воспроизводятся.
  В личке существующее уведомление о прерывании сохраняется; старая кнопка
  после перезапуска закрывает исходный статус при нажатии.
- В Guest с доступом к личным инструментам текст поискового запроса не выводится
  в общий чат: отображается только этап поиска.
- Дополнительного вызова модели для summary нет. Новых миграций нет.

Владелец предоставил https://t.me/addemoji/aelys_status. Read-only `getStickerSet`
подтвердил восемь animated custom emoji. Для уже существующих этапов выбраны:

- Подготовка ответа: 🤔, `5188364800450670260`.
- Веб-поиск: 🔍, `5199622193201333717`.

Статусы отправляют explicit `custom_emoji` entity поверх соответствующего
обычного emoji; ссылка trace и Stop сохраняются. Дополнительных запросов за
набором на каждом ходе нет. Остальные эмодзи набора не создают новых этапов.
Если Telegram явно отклоняет сообщение с custom emoji (HTTP 400), одна повторная
попытка без custom entity сохраняет рабочий статус. При неопределённой отправке
(timeout/network/5xx) повторного начального сообщения нет. Это особенно важно
для Guest Mode, где право на custom emoji отличается от прямых сообщений бота.
Документация: https://core.telegram.org/bots/api#formatting-options.

answer_trace_delivery, answer_format и transport — **139 passed, 1 skipped**.

Ruff всего backend, mypy (149 файлов), `git diff --check` — pass.
Перекрёстная проверка GPT-6.1 Sol: замечаний нет. Набор проверен read-only
