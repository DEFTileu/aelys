# AELYS Companion — фаза 5 «Голос» (дизайн)

Статус: **PROPOSED** — ждёт одобрения владельца.
Дата: 2026-11-15. Продолжение `2026-11-12-esp32-companion-design.md` (§4.9, фаза 5).

Пометки: **[владелец]** — решение владельца; **[моё решение]** — выбор автора дизайна, можно оспорить; **[открыто]** — ждёт владельца.

## 1. Зачем

На плате есть микрофоны ES7210, которые сейчас не используются. Владелец хочет дать им дело **[владелец]**: держишь кнопку, спрашиваешь AELYS голосом, Элис отвечает через свой динамик. Это голосовой вход в тот же AI, что стоит за Ask Aelys в приложении, а не отдельный ассистент.

Успех: вопрос «что у меня сегодня?» или «добавь задачу купить молоко» работает с платы. Ответ начинает звучать через несколько секунд после того, как отпущена кнопка. Разговор потом виден в AI-чате приложения. Плата при этом не теряет плавности и не выходит из бюджетов памяти §4.6 основного дизайна.

## 2. Цели, не-цели, анти-цели

**Цели:**
1. Режим «держи и говори» на верхней кнопке, запись до 20 с **[владелец: только по кнопке, 20 с]**. Пока Элис слушает, выключение платы долгим нажатием отключено **[владелец]**.
2. Распознавание речи и озвучка ответа через **ElevenLabs по API** **[владелец]**: STT — Scribe, TTS — **Eleven Flash v2.5** **[владелец: «пока v2.5, потом поменяем»]**. Модель задаётся в настройках провайдера, а не в прошивке.
3. Голос с платы может **спрашивать** (задачи, календарь, фокус, погода, общие вопросы) и **добавлять** (задачи, заметки) **[владелец: вариант 2]**. Добавление — сразу, без карточки подтверждения; лишнее владелец удалит сам **[владелец]**.
4. Диалог сохраняется в AI-чате приложения как обычный разговор **[владелец: «есть же Ask Aelys»]**.
5. Лицо отражает состояние: слушает → думает → говорит. Ночью (22:00–07:00) ответ показывается только текстом.

**Не-цели (возможно позже):**
- wake word «Привет, Элис» (ESP-SR WakeNet): постоянно включённый микрофон, лишняя RAM;
- распознавание на лету, пока владелец говорит (streaming STT) — позже можно добавить поверх §4 без изменений платы;
- озвучка по предложениям, пока AI ещё пишет ответ;
- казахский язык (Flash v2.5 его, по-видимому, не озвучивает; понадобится модель v3 — это смена настройки);
- перевод Telegram-распознавания и английского тренажёра на ElevenLabs;
- сжатие Opus.

**Анти-цели (провал, даже если «работает»):**
- голосом с украденной платы можно узнать почту, финансы, Telegram, память или содержимое заметок либо закрыть/изменить/удалить задачи;
- микрофон пишет без зажатой кнопки или без видимого «слушаю» на экране;
- звук сохраняется где-либо (бэкенд, логи, плата после ответа) или попадает в логи текстом расшифровки;
- ключ ElevenLabs на плате;
- звук из динамика ночью или в режиме пропажи;
- голос ломает плавность UI или опускает внутреннюю кучу ниже бюджета.

## 3. Ограничения и факты

- Плата: ES7210 (2 микрофона, I2S DIN GPIO 10), ES8311 + усилитель (PA_EN GPIO 46); общие MCLK 16 / BCLK 9 / WS 45; динамик уже работает на 16 кГц (`beep.h`, `board_audio.c`). Адреса ES7210 в `board_pins.h` нет. Конфигурация микрофона — по BSP Waveshare `esp32_s3_touch_amoled_1_75c` и xiaozhi-esp32 (поддерживает эту плату) как образцу.
- Память: при подключении `heap_int` ~104 КБ, крупнейший блок ~31 КБ. Порог «≥ 120 КБ» в §4.9 основного дизайна считался под Opus-кодек. В этом дизайне кодека нет, поэтому порог заменяется на §6.
- Канал `WS /api/v1/devices/channel` (`backend/app/companion/channel.py`): reader берёт только `event["text"]`, writer умеет только `send_json`. Плата (`link_ws.c`) отбрасывает бинарные кадры. Одно TLS-соединение за раз (заметка plan 4).
- Бэкенд: TTS нет. STT есть (`telegram_transcription.py`, `english/speech.py`), но под OpenAI-совместимый `/v1/audio/transcriptions`. ElevenLabs — другой API, поэтому нужен новый вид провайдера.
- ElevenLabs API (проверено по документации 2026-11-15):
  - STT: `POST /v1/speech-to-text`, multipart, `model_id` (`scribe_v1`/`scribe_v2`), `file_format=pcm_s16le_16` — сырой 16 кГц / 16 бит / моно little-endian, ровно то, что даёт микрофон;
  - TTS: `POST /v1/text-to-speech/{voice_id}/stream`, `output_format=pcm_16000`, `model_id=eleven_flash_v2_5`;
  - заголовок `xi-api-key`.
- AI: `personal_tool_registry` (`backend/app/ai/personal_tools.py`) — инструменты `list_tasks`, календарь, `create_task`, `create_note`, изменение задач и т. д. Права — через `PermissionContext` и Policy Engine. В веб-чате записи проходят через `gate_writes` (карточка подтверждения).
- Лицо: настроения `thinking` и `attention` уже есть (`face_moods.c`). Звуки глушатся ночью в `screens.c:152`.
- AGENTS.md: новый UI — только по макету, одобренному владельцем; изменения бэкенда — ADR; без новых сервисов без обоснования (ElevenLabs выбрал владелец, ключ — его, BYOK).

## 4. Подходы

| | Как | Плюсы | Минусы |
|---|---|---|---|
| **А. Сырой PCM по каналу** (выбран) | Бинарные кадры 16 кГц/16 бит/моно в существующем `wss`, туда и обратно | Нет кодека на плате и на бэкенде; без второго TLS; формат совпадает с ElevenLabs без перекодирования | ~32 КБ/с в каждую сторону |
| Б. Opus, как xiaozhi | Сжатие на плате, декодер на бэкенде | Трафик в ~10 раз меньше | Кодер Opus — десятки КБ RAM и большой стек; новая зависимость на бэкенде; выигрыш только на плохом Wi-Fi |
| В. Отдельный HTTP-запрос со звуком | POST аудио, ответ аудио | Проще протокол | Второе TLS-соединение (+22–42 КБ внутренней RAM), нарушает «одно TLS за раз» |

Владелец выбрал **А** **[владелец, 2026-11-15]**. Streaming STT отложен как улучшение, которое ложится поверх А.

## 5. Как устроено

### 5.1 Сценарий

1. Владелец зажимает **верхнюю кнопку** на любом экране, где она не занята действием (см. 5.4). Через 400 мс удержания начинается запись: лицо `attention` («слушаю»), короткий звук `SFX_OPEN` не играет (чтобы динамик не попал в микрофон) **[моё решение]**.
2. Плата шлёт `voice_start`, затем кадры PCM по 100 мс (3200 Б).
3. Кнопку отпустили → `voice_end`. Лицо `thinking`. Запись дольше 20 с обрывается платой (лицо даёт знак за 3 с до конца) и сервером.
4. Бэкенд: Scribe → текст → AI-ход с голосовым набором инструментов → текст ответа → TTS-поток → PCM обратно на плату.
5. Плата показывает текст ответа во всплывающем окне (существующий `scr_notice`) и проигрывает звук. Ночью, в режиме пропажи или при выключенном звуке в настройках — только текст.
6. Повторное нажатие во время ответа обрывает воспроизведение и начинает новый вопрос. Нижняя кнопка закрывает ответ (как сейчас закрывает `scr_notice`).

### 5.2 Протокол (добавка к `docs/companion-protocol.md`, раздел «Voice») [моё решение, имена полей — реализатору]

Плата → сервер:
- `voice_start {id, rate: 16000, format: "pcm_s16le"}` — `id` уникален в пределах устройства;
- бинарные кадры: сырой PCM. Одновременно идёт не больше одного голосового хода, поэтому кадр не несёт `id`;
- `voice_end {id}` / `voice_cancel {id}`.

Сервер → плата:
- `voice_state {id, state: "thinking"|"speaking"|"done"|"error", error_code?}`;
- `voice_text {id, text}` — текст ответа для экрана; до 600 символов, дальше обрезается;
- бинарные кадры: PCM 16 кГц моно, ≤ 4 КБ на кадр;
- `voice_state done` после последнего кадра.

Правила:
- бинарный кадр без активного `voice_start` сервер отбрасывает;
- запись больше 20 с (640 000 Б) → `error VOICE_TOO_LONG`;
- второй `voice_start` во время хода отменяет первый.

Коды ошибок: `VOICE_NOT_CONFIGURED` (нет провайдера ElevenLabs), `BUDGET_EXCEEDED`, `VOICE_TOO_LONG`, `VOICE_EMPTY` (Scribe вернул пустой текст), `VOICE_UNAVAILABLE` (сбой провайдера). Плата показывает их коротким текстом.

### 5.3 Бэкенд

- **Провайдер `elevenlabs`** **[моё решение]**: новый вид в `AIProvider`, ключ шифруется как остальные (`AIProviderSecret`). В `model_policy_json`:
  - `voice_id` — по умолчанию один стандартный многоязычный голос ElevenLabs, зашитый в бэкенде **[моё решение]**: поле выбора голоса в форме провайдера — новый UI и требует макета владельца, это позже;
  - `tts_model` (по умолчанию `eleven_flash_v2_5`);
  - `stt_model` (по умолчанию `scribe_v1`; если доступен `scribe_v2`, взять его — проверить на аккаунте);
  - `voice_request_cost` — резерв стоимости одного хода по образцу `transcription_request_cost`.

  Новая функция `voice` в `FEATURES` (`backend/app/ai/defaults.py`) с видом `("elevenlabs",)`. Вид `elevenlabs` и хост `api.elevenlabs.io` добавляются в проверки видов/хостов провайдеров (`backend/app/ai/api.py`, `egress.py`). Форма провайдера в настройках (`apps/web/src/views/ProviderSettings.tsx`) используется как есть: ключ, бюджет, стоимость запроса. Новых полей нет.
- **Канал**:
  - reader принимает `event["bytes"]`;
  - writer умеет отправлять байты (очередь outbox с типом кадра);
  - голосовой ход идёт отдельной asyncio-задачей на соединение и отменяется при разрыве;
  - аудиобуфер живёт только в памяти этой задачи и освобождается после хода.
- **Голосовой ход** (`backend/app/companion/voice.py`):
  1. Проверить бюджет по образцу `transcribe_audio`: резерв `AIRun` с идемпотентным ключом `companion-voice:{device_id}:{id}`. Коммит до ожидания провайдера.
  2. Scribe: сырые байты как файл с `file_format=pcm_s16le_16`. Таймаут 30 с, ответ ≤ 100 КБ.
  3. AI-ход через `run_tool_turn`, основная chat-модель владельца (функция `chat`). Голосовая системная подсказка: «отвечай коротко, 1–3 предложения, без markdown и ссылок, на языке вопроса».
  4. Ответ — в `voice_text`, затем TTS-поток. Кадры уходят на плату по мере прихода.
- **Разговор**: один `AIConversation` на устройство («Элис — голос»), id хранится на `Device` по образцу `personal_conversation_id` в Telegram. В разговор пишутся текст вопроса и текст ответа, звук — никогда. Расшифровка и ответ не попадают в логи.
- **Права голоса** (fail-closed):
  - реестр собирается из `personal_tool_registry` и **оставляет только** инструменты по allow-list имён: `list_tasks`, `read_calendar`, `create_task`, `create_note`. Список по именам, а не по scope: `tasks.write` открыл бы и `update_task`/`complete_task`;
  - записи выполняются сразу, `gate_writes` не применяется **[владелец]**. Ответ Элис подтверждает, что именно добавлено («добавила задачу „купить молоко“ на завтра»);
  - **каждый голосовой ход — без истории** **[моё решение]**: в AI-ход идут только системная подсказка, контекст снапшота и текущий вопрос. Иначе тот, кто держит плату, мог бы спросить «о чём мы говорили» и услышать то, что владелец писал в этом разговоре в приложении. Цена: уточнения вроде «а завтра?» не работают;
  - `PermissionContext(actor="companion-voice:{device_id}", scopes={tasks.read, calendar.read, tasks.write, notes.write}, policy_id="companion-voice")`;
  - без памяти, без веб-поиска, без внешних эффектов;
  - фокус и погода передаются в подсказку из того же снапшота, что видит плата (`snapshot.py`), а не инструментом.
- **Права платы**: голос идёт по каналу, поэтому HTTP allow-list `COMPANION_ALLOWED` не меняется. Типы сообщений `voice_*` принимаются только от устройства `companion` этого владельца.
- **ADR**: следующий свободный номер в `docs/DECISIONS.md` (plan 4 занял ADR-030, plan 3 мог занять ADR-031 — проверить). Миграция Alembic — следующая свободная (поле разговора на `Device`).

### 5.4 Прошивка

- **Кнопка** (`screens.c`, `screen_fsm.c`):
  - удержание верхней кнопки ≥ 400 мс начинает голос на экранах, где верхняя кнопка лишь открывает меню (Home, Today) **[моё решение]**. На экранах, где верхняя кнопка — действие (Focus, Tasks, Timer, Games), голос не включается: короткое нажатие делает своё, как сейчас;
  - короткое нажатие (< 400 мс) срабатывает по отпусканию — сейчас меню открывается по нажатию, это меняется;
  - если за время удержания нажата нижняя кнопка — голос отменяется, комбинация ICE (обе кнопки 2 с) имеет приоритет;
  - **выключение долгим нажатием** **[владелец]**: верхняя кнопка, по всей видимости, — PWR-кнопка AXP2101 (соответствие в `board_input.c` ещё не проверено на плате). AXP2101 выключает плату после 10 с удержания (`AXP_OFF_10S` — максимум регистра), поэтому на время записи выключение долгим нажатием отключается (бит в регистре PWROFF_EN, 0x22; в XPowersLib это `disableLongPressShutdown()` — сверить с даташитом). Включается обратно: при отпускании, при обрыве записи, по сторожевому таймеру через 25 с и при каждой загрузке. Логику «устаревшего» нажатия `PWRKEY_STALE_MS` (10,5 с) на время записи нужно расширить. Если отключить нельзя — запасной вариант: запись до 8 с;
  - в режиме пропажи голоса нет.
- **Аудио** (`board_audio.c`):
  - расширить до режимов «запись» и «поток воспроизведения» на I2S0 в полудуплексе по очереди: сначала RX ES7210, затем TX ES8311 **[моё решение: одновременная запись и воспроизведение не нужны, перебивание просто останавливает звук]**;
  - всё создаётся на время хода и разбирается после, как сейчас для звуков;
  - «Найди Элис» прерывает голос;
  - звуковые эффекты во время голосового хода не играют.
- **Память**:
  - буферы записи (кольцо ~1 с) и воспроизведения (кольцо до ~4 с, 128 КБ) — в PSRAM;
  - DMA-дескрипторы I2S — маленькие, во внутренней RAM (как сейчас, ~2.5 КБ);
  - стек голосовой задачи — в PSRAM, если это безопасно с учётом записей во флеш (NVS) при отключённом кэше; иначе внутренний ≤ 6 КБ (реализатор проверяет).
- **Канал** (`link_ws.c`, `proto.c`):
  - отправка бинарных кадров;
  - приём бинарных кадров в кольцо воспроизведения (без копии в текстовый буфер `LINK_FRAME_MAX`);
  - сообщения `voice_*` — в чистой логике `proto.c` с тестами на хосте.

  Если сервер шлёт быстрее реального времени и кольцо полно, плата не теряет звук: задача `net` ждёт (TCP сам притормозит сервер) **[моё решение]**.
- **Лицо и экран**:
  - `attention` пока идёт запись;
  - `thinking` от `voice_end` до первого звука;
  - во время ответа — обычное лицо и `scr_notice` с текстом;
  - индикатор записи — существующее настроение, без нового макета. Если владелец захочет отдельный «слушающий» экран — это отдельный макет.
- **Ночь**: ход идёт, но `voice_text` показывается без звука; плата сообщает об этом серверу в `voice_start` (`speak: false`), сервер тогда не вызывает TTS (экономия денег) **[моё решение]**.
- **Офлайн**: удержание кнопки показывает «нет связи», запись не начинается.

### 5.5 Задержка и стоимость

- Цель: от отпускания кнопки до первого звука **≤ 4 с** при ответе в 1–3 предложения. Ориентиры: Scribe ~0.5–1 с, AI ~1–2 с, первый кусок TTS ~0.3 с. Замерить на реальном аккаунте и записать в ADR.
- Стоимость: резерв `voice_request_cost` на STT+TTS и обычный учёт AI-хода. Всё в месячном бюджете владельца. Сверх бюджета — `BUDGET_EXCEEDED`, ход не начинается.

## 6. Память — ворота и замеры

Замена порога 120 КБ из основного дизайна **[моё решение]**. В `firmware/companion/docs/next-steps.md` записан `heap_int_min` 41 КБ офлайн — это ещё не объяснено, поэтому фиксированный порог заменён на относительный. Голос включается в прошивку, если **за полный голосовой ход** (запись 20 с + ответ 20 с, 10 ходов подряд) выполняется:
- минимум внутренней кучи опускается **не больше чем на 16 КБ** относительно минимума ONLINE без голоса за тот же час;
- крупнейший блок ≥ 24 КБ (TLS-переподключение должно пройти во время хода);
- UI держит 60 fps, худший кадр ≤ 25 мс;
- `heap_int` после хода возвращается к значению до хода (нет утечки).

Порядок:
1. **Замер до кода голоса**: текущий минимум кучи в ONLINE за час с метриками.
2. **Запись без звука**: микрофон → PSRAM → выброс, плюс отправка на сервер. Проверка ворот без динамика (владельцу ничего не слышно).
3. Только после этого — воспроизведение.

Если ворота не проходят, освобождение памяти — часть фазы, и голос ждёт. Начать с объяснения 41 КБ. Первые кандидаты:
- уменьшить DMA-буферы LVGL;
- проверить `CONFIG_SPIRAM_TRY_ALLOCATE_WIFI_LWIP` и mbedTLS dynamic buffers из §4.6;
- перенести стеки, которым не нужна внутренняя RAM, в PSRAM.

2. Прошивка, чистая логика: протокол `voice_*`, автомат «держи и говори» (кнопки, ICE, отмена), тесты на хосте.
3. Прошивка, плата: запись ES7210, отправка, замеры §6. **Без звука из динамика.**
4. Прошивка, плата: воспроизведение потока. **Первая проверка вслух — только после «да» владельца** (правило «без звука без спроса»).
5. Сквозная проверка с реальным ключом ElevenLabs владельца (ключ вводит владелец в настройках).

Мерж, деплой и прошивка — только с «да» владельца.

## 8. Оставлено реализатору

- Точные имена полей протокола, размер кадров, разметка кольцевых буферов.
- Настройка ES7210: усиление, какой из двух микрофонов брать или как их смешивать — калибровать на плате, по образцу BSP/xiaozhi.
- Стек голосовой задачи: PSRAM или внутренняя RAM — по результату проверки.
- Тексты ошибок на экране — короткие, в стиле существующих тостов.
- Где хранится id голосового разговора: поле `Device` или таблица привязки.

## 9. Решения владельца и что открыто

Решено 2026-11-15:
- только по кнопке, без wake word;
- голосом можно спрашивать и добавлять (вариант 2);
- диалог — в AI-чате приложения;
- STT и TTS — ElevenLabs по API, TTS — Flash v2.5, модель меняется настройкой;
- подход А (сырой PCM по каналу);
- запись до 20 с, выключение долгим нажатием отключено на время записи;
- задачи и заметки добавляются голосом сразу, без подтверждения.

Решения автора, которые владелец может оспорить:
- голосовой ход без истории разговора;
- один стандартный голос ElevenLabs до макета поля выбора голоса;
- относительный порог памяти (−16 КБ) вместо 120/80 КБ;
- голос только на Home/Today, где верхняя кнопка открывает меню; меню — по отпусканию короткого нажатия;
- ночью TTS не вызывается вовсе, ответ только текстом.
