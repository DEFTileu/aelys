# Aelys — Product Requirements Document (PRD) v1.0-draft

## 1. Product statement

Aelys — self-hostable, open-source, **single-user Personal OS** для системной работы с собственными задачами, знаниями, событиями, финансами, почтой, временем, проектами и AI. Функционирует на Web, macOS и Android APK; общие данные синхронизируются; на Mac исполняются локальные Claude Code / Codex CLI.

### Продуктовые цели
- Одно место для организации личной и проектной информации вместо множества изолированных приложений.
- Надёжная работа без интернета с последующей согласованной синхронизацией.
- AI-ассистент понимает связи между данными и умеет исполнять разрешённые действия.
- Приватная история локальных агентов; внешние запросы к ней — лишь через контролируемый Mac Runtime.
- Возможность самостоятельной установки всей системы, без обязательной proprietary платформы.

### Пользователь
Первичный: один владелец аккаунта с несколькими доверенными устройствами. Поддержка команд/организаций/коллаборации **не входит** в MVP; но архитектура не должна полагаться на глобальный статический пользовательский ID.

## 2. Функциональные требования

Обозначения: `MUST` — требуется в соответствующем целевом MVP, `SHOULD` — желательно в следующей поставке, `OPEN` — функциональный объём надо уточнить.

### 2.1 Core / Projects (MUST)
- Создание, архивирование, переименование и удаление проекта с безопасным подтверждением необратимых операций.
- Связывание note/task/event/file/AI chat/agent session/repository с одним или несколькими контекстами проекта в рамках выбранной модели.
- Объекты, не принадлежащие проекту (personal inbox/notes/tasks).
- Просмотр истории изменений объекта; стабильный UUID.
- Один владелец данных с контролем устройств/сессий.

### 2.2 Notes & Knowledge (MUST)
- Создание/редактирование Markdown-заметок, теги, поиск, внутренние ссылки, вложенность/организация в папки либо страницы (способ OPEN).
- Версии/восстановление, безопасное хранение конфликтующих редакций.
- Вложения и индексация разрешённых текстовых данных; тяжёлый OCR не является MVP.
- Работа offline с последующим sync.

### 2.3 Tasks & Projects (MUST)
- Создание/изменение задачи, подзадачи, статус, приоритет, дедлайн, теги, список задач по проекту.
- Повторение задач, напоминания и прикрепление заметок/событий.
- Агрегирование задач по сегодня/просрочено/ожидается.
- Надёжная отправка уведомления без дублей при смене часового пояса/устройства.

### 2.4 Calendar (MUST)
- Локальные события, start/end в timezone-aware формате, алл-дей, повторения, напоминания и связь с задачами.
- Offline создание/редактирование; отображение конфликтов вместо скрытой потери записи.
- Внешний Google Calendar после подключения интеграционного адаптера (не обязательная зависимость Core).

### 2.5 Mail (MUST — модель; provider connectivity OPEN)
- Единая доменная модель письма, треда, черновика и извлечённых задач.
- Безопасный поиск по импортированным/полученным письмам; AI summary по явному разрешению.
- Создание черновика ответа, отправка только если предоставлен sender-адаптер/право.
- **OPEN:** живой Gmail OAuth в MVP либо импортер/локальная модель с дальнейшим расширением. Не делать ложных заявлений о «работающей почте» при отсутствии провайдера.

### 2.6 Finance (MUST)
- Ручной ввод расходов/доходов/переводов, категории, счета, бюджеты и валюты (KZT по умолчанию как доступная настройка, не захардкоженная единственная валюта).
- Суммы хранятся decimal/minor-units, не binary float; курс валют имеет источник, дату, базовую и целевую валюты.
- Offline транзакции с устойчивой idempotency; отчёты по категории/периоду.
- Прямые банковские подключения, автоплатежи и инвестиции не обязательны.

### 2.7 Timer / Focus (MUST)
- Pomodoro, custom timer, stopwatch, пауза/возобновление, связь с задачей/проектом.
- История фокус-сессий и суммарные минуты.
- По возможности offline; таймер должен восстанавливаться из elapsed timestamps, не зависеть от постоянно запущенного JS/таймера.
- Конфликт одновременного управления таймером с двух устройств должен быть явно разрешён протоколом.

### 2.8 Telegram Bot (MUST — бот требует внешней сети)
- Только авторизованный Telegram user ID привязан к владельцу; первоначальная привязка с одноразовым кодом.
- Capture: `/task`, `/note`, `/today`, `/remind` и уведомления о разрешённых событиях.
- Повторно доставленные webhook updates не создают дублей.
- Никакого раскрытия секретов, полной истории agent sessions и чувствительного содержания по умолчанию.
- Подтвердить фактический объём первого релиза (OPEN).

### 2.9 AI Chat & BYOK (MUST)
- Настройка API-провайдеров и моделей, ручной override, авто-роутинг по задачам, бюджет и счётчик затрат.
- История чатов по проектам/общая, stop/abort и потоковые ответы.
- Tool calling для read/write операций; Policy Engine определяет фактическое право на выполнение.
- Ответы с ссылками на источники (resource IDs, local source refs) и понятным поведением при offline источнике.
- Не считать content из документов/писем/system logs доверенными инструкциями.

### 2.10 Mac Agents (MUST — поэтапно)
- Обнаружение/импорт истории Claude Code и Codex CLI через локальные адаптеры, в рамках разрешённых папок/профилей.
- Полная история и FTS **остаются на Mac**; облачные записи содержат только нейтральные метаданные без содержательного текста.
- Запросы на поиск с других устройств маршрутизируются Mac Runtime; Mac offline => «источник недоступен».
- Удалённый запуск нового задания в явно авторизованном проекте, поток статусов, отмена, результат.
- Никаких подтверждений на каждый шаг **внутри sandbox и политики проекта**; недопустимо предоставлять весь `$HOME` или сетевые полномочия без отдельного разрешения.
- CLI-версии и поддержка продолжения сессий проверяются адаптерно.

### 2.11 Automation / Activity (MUST — минимальное ядро)
- `trigger → conditions → actions`, enable/disable, лимиты частоты, dedup, retries, audit.
- Действия модулей только после policy validation; небезопасные операции — отдельный grant.
- Журнал результат/источник/исполнитель, ошибки/повторное выполнение.

### 2.12 Dashboard, Search, Settings (MUST)
- Сводка задач, календаря, фокуса, текущего дня и состояния устройства/синхронизации.
- Единый поиск по доступным объектам; поиск Mac-only сессий делает Mac, не облачный индекс.
- Управление устройствами, ключами/провайдерами, доступом к проектам, приватностью, sync и экспортом.

## 3. Ограничения offline

| Функция | Без сети |
|---|---|
| Notes, Tasks, Calendar, Finance, Timer | Да, на доступных локально данных |
| Projects, локальный поиск | Да |
| История Mac agents на Mac | Да |
| Вопрос о Mac agents с Android при выключенном Mac | Нет (только metadata) |
| Облачный AI | Нет (история и drafts доступны offline) |
| Отправка/получение почты, Telegram | Нет, операции могут быть поставлены в очередь при корректной семантике |
| Доставка push/синхронизация других устройств | Только при сетевом доступе и ограничениях ОС |

## 4. Nonfunctional Requirements

- Данные не теряются при разрывах сети, ретраях и конфликтующих изменениях.
- Права на локальные директории и AI-инструменты по принципу наименьших полномочий.
- Нет секретов и raw agent sessions в облачных логах, метриках и crash reports.
- API versioning `/api/v1`; миграции схем с roll-forward/rollback, когда безопасно.
- Observability: structured logs (redacted), trace/operation/run IDs, измерение sync lag и tool errors.
- Portable / self-hostable, открытый исходный код и инструкции установки.
- Для запросов с внешним эффектом — audit, idempotency, ограничение стоимости/времени.

## 5. Не входит в MVP

Командная многопользовательская работа, публичная социальная сеть, банковские интеграции, полноценный AI offline LLM, голосовой ассистент, многоплатформенное исполнение coding agents на любой ОС, браузерная автоматизация без явных полномочий, Infrastructure Monitor, самостоятельное написание дизайна.

## 6. Критерии выпуска

См. [`ACCEPTANCE_TESTS.md`](ACCEPTANCE_TESTS.md). Готовность — не количество созданных экранов/файлов, а работающие end-to-end сценарии с проверкой recovery, безопасности и данных.
